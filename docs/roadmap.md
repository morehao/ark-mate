# Roadmap

> **本文件是排期的唯一出口。**定位与边界不在这里（去 [`positioning.md`](./positioning.md)），
> 口径变更的历史与代价不在这里（去 [`decisions.md`](./decisions.md)），能力缺口不在这里
> （去 [`unimplemented.md`](./unimplemented.md)）。
>
> **排期规则**：每个阶段给的是**出口判据**（可证伪、可挂到一条命令上），不是「做完什么」。
> 一项工作若说不出「怎么证明它做完了」，它还没到能排期的程度。
>
> **三段的关系**：`L` 段是**承诺**（在做/要做，出口判据齐全）；`B`/`C` 段是**方向**——
> 保留能力位、写清依赖与风险，**不排期、不作承诺**（决策 v8② 对「不追求数量」的同一口径：
> 方向性路线不该被读成里程碑）。

本地形态已经可用：ACP 直连（内置 `dsh`）、会话与轮次、结构化提问与权限确认、能力数据面

剩下的问题都写在 [`unimplemented.md`](./unimplemented.md) 里——那份清单是 L 段的输入。

## L 段 · 本地（承诺）

### L1 · 口径收口（进行中）

**做什么**

1. **文档重建**：`docs/` 收敛为「定位 / 决策登记 / 架构 / 路线图 / 未实现清单 / 验收矩阵 / 部署 /
   底座适配」八件，旧的设计文档整体归档（历史留在 git 里）。参照产品的对照与逆向内容**不进
   `docs/`**，一律落 `.dsh/docs/`。
2. **后端目录收口**：`internal/manager` 一个包吃掉全部业务（146 文件 / 307 个方法 / 30+ 字段的
   god struct），而同域的 `service/svc*`（9 个包、平均 44 行）与 `dto/dto*`（11 个）是纯转发的包税——
   **纵向太散、横向太厚同时发生**。分两步：先「按域搬家、行为零变化」，再拆 god struct。

**出口判据**

- `go test ./internal/archtest/` 全绿（79 条 + 新增的文档引用守卫）；
- 新增一条 fail-closed 守卫：`README.md` / `AGENTS.md` / `docs/**` 里指向 `docs/**` 的路径必须存在
  （今天有一处断链，且没有任何机制会红）；
- 后端搬家完成后：`make build && make vet && make test` 全绿 + `make verify/desktop-dod` 通过
  （「行为零变化」这件事只能靠这两条证伪）。

### L2 · 未实现清单清零

**做什么**：把 [`unimplemented.md`](./unimplemented.md) §2 的 OPEN 条目逐条决策——**做**（排进 L3 或
单独立项）、**不做**（移进 CLOSED 并写明理由）、或**改判为 DEGRADED**（底座/SDK 不提供，平台如实降级）。
候选按「用户能感知」排序：

| 候选 | 为什么值得先看 |
|---|---|
| O3 · MCP 工程化（连接池 / 限流 / 审计） | 远程 MCP 已经过网关成为常态路径，但每次调用一次 spawn/握手、调用结果不进事件流 |
| O2 · 配置热重载 | 改能力定义或 MCP 都要重启；这是「开箱即用」这条定位的直接摩擦 |
| O13 · 事件持久化边角 | 写库失败的事件不进 REST 历史——「历史与实时不一致」是排障时最难解释的一种 |
| O11 · 权限策略精细化 | 「总是允许」目前是会话级记忆；按工具参数匹配是用户真实需要的那一档 |
| O7 / O8 / O9 · 导出、用量、分页的增强面 | 都是"能用但不够"的档，触发条件明确 |

**出口判据**：`unimplemented.md` §2 不再有「未决定」的条目——每条要么有排期、要么有理由、要么改判。

### L3 · 可靠性借力

**做什么**（每项都是「静默失效」型问题，代价小、收益是结构性的）：

1. **启动过程显式建模**：现在 `dev-loop` 有阶段监督（任一阶段死即整体回红），但缺一张「带预算与降级
   策略的启动步骤表」——每个步骤带 `critical` / 超时 / 依赖，把「启动」从一串 `await` 变成可观测、
   可限时、可降级的状态机。
2. **权限的「总是允许」绑到当初那次具体授权**，而不是一个布尔标志。现在会话级记忆是
   `{title, kind, decision}` 的键；绑到具体授权形态能挡住「同名工具换了参数沿用旧授权」。
3. **审计表加哈希链**：`definition_revisions` 现在每条独立；加 `prevHash`/`hash` 后，「事后能否发现
   被改过」变成可判定的，实现代价极小。
4. **投递与执行的解耦（事务性 outbox）**：automation 的「跑完」与「结果送达」现在是同一条路；
   通道投递失败是常态而非例外，拆开后重试语义才干净。
5. **注入面的字节预算与截断可回读**：AGENTS.md / skill 正文进入上下文是有预算的，超限要截断；
   截断提示必须带完整路径与可回读的定位信息，否则「截断」等于信息丢失。

**出口判据**：每一项都要落一条静态或动态判据（这条是本仓的取向：**没有判据的纪律等于没有纪律**），
例如权限记忆那项必须有一条守卫钉住「键里带授权形态」。

## B 段 · 端云桥接（方向，不排期）

云端不是「另做一个产品」，而是把已经存在的接缝升格。**当前已有的地基**：`pkg/acl` 的两套远程传输
（Streamable HTTP / WS）、`runtimes.json` 的远程端点声明、以及「只有构建期选中的那个 id 命中声明时
才注册」这条 fail-closed 装配。

| 项 | 方向 | 依赖 / 风险 |
|---|---|---|
| **B1 身份** | 本机身份 ↔ 远端身份的映射。**仍不做多租户**（那是 C 段的事） | 现在「单操作员」是红线（决策 v3③），B1 必须在不推翻它的前提下铺路 |
| **B2 远程执行面升格** | 让「会话跑在远端」成为一等形态（会话带 `transport=local\|cloud`） | 传输已具备；缺的是产品形态、失败语义与降级路径 |
| **B3 端云同步** | 会话 / 工作空间 / 定义（provider / model / skill / mcp）三类同步 | **必须自带一致性守卫**：同步面最容易出现「两套口径没有守卫」与「同一事实两个来源」。同步的幂等要用**数据库约束**表达，不要在应用层「先查一遍再决定插不插」 |
| **B4 数据面与密钥面** | `store` → 可选服务端库；密钥从「库内明文 + 0600 镜像」升级 | v20 已经把代价如实登记：**库与其备份含明文**，共享机器不安全。上云前这条必须结清 |

**共同前置**：B 段的每一项都会触碰「读模型可重建」「身份与位次分离」「凭据分层」这些现有不变量——
**先写不变量，再写同步**。

## C 段 · 云端（方向，不排期）

| 项 | 方向 | 关键取舍 |
|---|---|---|
| **C1 云端执行宿主** | adapter 上服务端 + 会话在云端沙箱执行 | 沙箱边界要**可判定**，不能靠「用户看不见」；本地形态里「平台的子进程 = 用户的机器」这条假设在这里失效 |
| **C2 账号与多租户** | **正式推翻决策 v3③ 的单操作员红线** | 这是破坏性变更，必须先登记决策（含代价），再动手。租户边界优先用**复合主键/约束**表达，而不是每条查询记得加 `WHERE` |
| **C3 云端能力面** | 企业策略下发 / 市场分发 / 计费 / 遥测 | 三条硬要求：**遥测必须有本地总开关**；**计费与权益单一事实源**；**策略下发不可用时本地行为要显式降级**，不能静默变成"看起来配了、其实没生效" |

**C 段的判断标准只有一条**：它能不能在**不改动 L 段那些不变量**的前提下落地。做不到，就先改不变量
（并登记决策），不要绕。
