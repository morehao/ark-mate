# 定位

> **本文是定位的对外口径**；定位的**变更历史与代价**登记在 [`decisions.md`](./decisions.md)
> （唯一事实源）。两者冲突时以决策登记为准——本文只陈述「现在是什么」，不解释「为什么变成这样」。

## 一句话

**底座 + 其上的个人 Agent 助手**：底座是做成的 `mate` 内核（多 runtime 统一接入 + 会话与能力数据面
+ REST/WS 契约 + 交付形态），其上是面向用户的**个人 Agent 助手**，**聚焦桌面端**；单机、单操作员、
开箱即用，执行能力来自 ACP 兼容的开源运行时（当前内置 `dsh`）。

> A personal agent assistant on top of a reusable agent core — ACP-compatible executors behind one
> control plane. Desktop-first.

## 两层结构（职责并列成立）

| 层 | 是什么 | 面向谁 |
| --- | --- | --- |
| **底座层** | `mate` 内核：多 runtime 统一接入 + 会话与能力数据面 + REST/WS 契约 + 交付形态 | 「把控制面接到自己的 runtime / 自己的前端上」 |
| **产品层** | 底座之上的**个人 Agent 助手**：建会话、跑起来、看见过程与结果 | 「我自己的助手」 |

两层**没有主次**——不是「先是产品、其次顺带提供底座」，也不是「先做平台、控制台只是演示面」。

## 交付形态

| 形态 | 状态 |
| --- | --- |
| **桌面**（macOS / Windows，随包运行时——用户机器不需要 Go / Node / 预装底座） | **主线交付**，主线排期只推进它 |
| **浏览器入口**（`make dev`） | **开发形态**，不是交付面；服务的是与交付态**同一份产物** |
| 容器 / 自建二进制 + 外挂 dist | **维护态**：保留可用、继续被测试、可修缺陷；不加新功能、不进主线排期 |

**一份 UI 产物，两种加载方式**：`frontend/apps/web/dist` 是唯一一份界面产物，核心**从不自带**资产
（调用方用 `--web-dir` 指过去，没给就拒绝启动）。两个入口**都没有 HMR/Fast Refresh**——改完 UI 等一次
增量重建，开发态由核心推一帧整页刷新。

## 五条边界

1. **能力不重造**。skill 执行、MCP 工具调用、推理循环等**运行时能力**一律直接复用底层 runtime 的原生
   实现；平台只做这些能力对应的**数据与配置管理**（会话数据、skill 数据、MCP 数据），不实现任何 agent
   运行时功能本身。
2. **数据管理是平台职责**。会话数据（wire transcript / 历史回放 / 读模型）、skill 数据（技能包存储与
   分发）、MCP 数据（服务器定义与注入面）以平台的库为事实源；写面按载体分叉，
   **读模型一律可重建**。
3. **单机单操作员**。不做多用户 / 团队共享 / 登录与 RBAC；控制面默认只绑回环；凭据体系只解决
   「REST 面与事件流面分权」。跨 agent 协作（委托 / 子 agent / 并行）同样不在定位内——**一次会话
   只绑定一个 runtime**。
4. **底座由构建期固定，用户不能选 runtime**。选中的 id 在编译期注入，不注入即 `dsh`；用户面没有任何
   runtime 选择或读取入口，带被撤掉的**选择键**的写请求一律**显式拒绝**（不静默丢弃——静默会让它变成
   「写了、存了、什么都不发生」的骗人字段）。
5. **接边有界**。内置适配只有 `dsh` 一个，**不追求数量、不承诺接入任意 ACP 生态**。但 adapter 层是
   完整的：接一个新底座 = 新建 `internal/adapters/outbound/<id>/`（实现 `runtime.Adapter`）+ 装配根加一行 + 挂三张**端口**实现
   （`resource.Syncer` / `runtime.NativePermissionAdapter` / `runtime.ModelValueAdapter`），
   **不需要改框架内核**。「配置化接入」是工程能力，不是定位承诺——真实成本在维护面
   （隔离表三份 / 投影实测 / 能力粒度声明 / 随包载荷与 ABI 断言），不在 adapter。

## 明确不做

以下都在边界之外，**新增这类需求必须显式走定位评审**（它们的入口是 [`decisions.md`](./decisions.md)，
不是某次实现顺手加进去）：

- **桌面 IDE 外壳**：编辑器、终端、文件树、Split View、canvas。注意「聚焦桌面端」说的是交付优先级，
  **不等于**做 IDE 外壳。
- **多人协作**：多用户、团队共享、登录 / RBAC、计费。
- **远程会话通道**：聊天 / webhook / IM 通道接入。
- **跨 agent 协作**：@委托、子 agent、并行编排。
- **运行时能力本身**：skill 执行器、MCP 客户端语义、推理循环、工具循环。
- **四个从没实现过的「桌面多给」方向**（打开文件/文件夹、导出诊断包、深链接、自更新）：它们不在产品面
  内，要做就**按功能单独立项**（连同浏览器侧的等价交互一起设计），不从任何清单里往回捡。
- **用户自定义 agent**：agent 概念已整个并入 runtime（底座构建期固定、能力由会话级 `capabilities`
  与平台默认决定）。将来若要恢复「按任务切分权限」，应作为 **runtime 的会话级配置**出现，而不是把
  agent 概念请回来。

## 三条一致性的取向

这三条不是功能，是**判据**——它们决定了上面每一条边界能不能被机器守住：

1. **一份产物、同一套契约、同一份数据、同一套 DoD**——不为了某个入口分叉出第二份实现。
2. **桌面只能「多给」，多给的那半必须有服务端等价路径**。差异清单与两侧靶见
   [`acceptance-matrix.md`](./acceptance-matrix.md)。
3. **fail-closed，且必须能被机器判定**：一条纪律要么有判据，要么被显式登记为「靠人执行」。
   判据的集中地与取向见 [`architecture.md`](./architecture.md) §10 与 [`docs/agents/guards.md`](./agents/guards.md)。
