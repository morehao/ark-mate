# 产品功能说明

> **这份文档是什么**：ark-mate 作为「个人 Agent 助手」当前具备的**产品功能清单**——按用户能感知到的
> 能力组织，每项说清「能做什么、边界在哪」。**机制细节不在这里展开**，逐条链到
> [`architecture.md`](./architecture.md) 的技术章节、[`agents/`](./agents/README.md) 的纪律分册与
> [`unimplemented.md`](./unimplemented.md) 的未实现清单。
>
> **读者**：想了解"这个助手能干什么"的人，以及要给某个功能补文档/改实现的开发者。
> **口径优先级**：定位与边界以 [`positioning.md`](./positioning.md) 与 [`decisions.md`](./decisions.md)
> 为准；本文只陈述"有什么"，不解释"为什么这样定"。

---

## 1. 会话问答（主视图）

会话页就是主界面：左侧会话侧栏，右侧流式对话。

- **多轮会话**：一条会话可连续多轮提问；首条用户消息自动推导标题。
- **流式渲染**：assistant 正文、思考（thought）、工具调用卡逐字流式呈现；正文里 ``` 围栏代码段渲染为带
  语言/行数、可复制、长块可折叠的代码卡片；消息可一键复制全文。
- **失败轮就地重试**：以 `run.error` 收尾的轮次，聊天流错误条与会话详情面板都提供「重试该轮」。
- **中断续聊**：进程重启前未收尾的会话标记 `interrupted`，可续聊重发；任何已存在的会话重启后都能继续提问。
- **会话管理**：置顶 / 归档 / 重命名；侧栏按「置顶 / 今天 / 昨天 / 更早」分组，含「会话 / 归档」双视图。
- **会话搜索**：按标题与正文搜索会话；跨会话消息级检索返回定位锚点，点击命中即跳转到该条消息。
- **导出**：批量导出 markdown / text / json，产物以事件序列为事实源，两种存储模式一致。
- **直达与续看**：`/sessions/:id` 直达激活，刷新/冷启动按游标续传补齐会话视图，断线自动重连（带 reconnecting 横幅）。

> 机制：会话执行、断连语义见 [`architecture.md`](./architecture.md) §3、§6.2；事件模型与 wire transcript
> 见下文 §12。

## 2. 对话中的交互决策

Agent 执行中需要人拍板时，平台把请求变成可交互的卡片：

- **权限确认**：agent 请求工具权限时弹权限卡（允许一次 / 始终允许 / 拒绝一次 / 始终拒绝）。「始终允许 /
  始终拒绝」记为**会话级记忆**，后续同键自动放行；记忆可列出、可单条或一键撤销。超时自动拒绝。
- **结构化提问（elicitation）**：agent 发起提问时，按 JSON Schema 渲染单选 / 多选 / 文本 / 数字 / 布尔
  表单并本地校验必填与范围；也支持 URL 模式引导链接。用户可提交 / 拒绝提供 / 取消，超时自动取消。
- **待确认角标**：权限 + 提问合并计数，任何终局（提交 / 拒绝 / 取消 / 超时）都以服务端收敛事件为准。

> 机制：两条通道的 scope 归属、决策回执、超时语义见 [`architecture.md`](./architecture.md) §6.2、§7.5，
> 以及 README 对外契约摘要里的 `/sessions/:id/permission|elicitation`。

## 3. 排队与插话（busy input 队列）

会话正忙时不必等——输入框不锁死：

- **排队（after_run）**：当前轮结束后自动投递下一条。
- **打断并发送（interrupt_then_prompt）**：取消当前轮后立刻投递。
- 已排队但未发出的条目实时列出，可逐条**撤下 / 行内编辑 / 重排 / 立即发送 / 取出编辑**。
- **排队项可带附件**（v38）：入队时本轮附件 id 随队项落库，投递时原样带出，不会「排了队附件却没了」。
- 顺序严格 FIFO，插话不插队；失败轮不自动续投，进程停机不投（重启时统一作废，不替用户按下发送）。

> 机制：投递判据（执行代际）、三态事件、审计台账见 [`architecture.md`](./architecture.md) §6.2 与 README
> 契约摘要的 `/sessions/:id/inputs*`。

## 4. 能力数据面：Skill / MCP / Tool

平台管理 skill、MCP server、tool 三类能力的**数据与配置**，执行一律归底座。

- **能力目录**：`/capabilities` 全局目录列出全部 skill / mcp / tool；会话能力条技能行可查看物化体检（逐 runtime 投放状态）。
- **Skill**：定义存储、启停（overlay，随时可恢复）、正文入表前威胁扫描（critical 直接拒载）、导出为
  底座可读的原生技能文件（物化）；支持 `.zip` 技能包导入。
- **MCP server**：定义、探测（`tools/list`）、调用工具、读资源、取提示词；stdio / http / streamable_http / sse
  四种传输。**明文与密钥分离**——密钥只以引用形式存在，读模型只回键名。
- **远程 MCP 经平台网关代连**：远程 server 由平台代连，底座侧只注入一条恒定条目，增删改不再换代际。
- **会话钉住能力子集**：一条会话可只启用技能 / MCP 的一个子集（逐类三态），选定即解析出**能力指纹**，
  决定用哪套能力代际，**下一个轮次边界**生效。

> 机制：三表、投影与物化、MCP 网关、能力指纹与代际、权限投影的完整设计见
> [`architecture.md`](./architecture.md) §7.1–§7.6；写面错误语义见 README 契约摘要与业务错误码段。

## 5. 专家（Expert）

**会话级能力预设**——把「推荐模型 + 推荐技能/MCP + 角色设定」打包成一个可选专家。

- 专家定义含名称、描述、头像、推荐模型、推荐技能、推荐 MCP、标签、`instructions`（角色设定正文）。
- 建会话或改能力时**可选一个专家**，专家只填空缺（显式 > 专家推荐 > 平台默认），不可达的推荐跳过并给出 warning。
- 专家是会话级预设，**不拥有技能、不新增 agent 身份层**；改专家定义不影响已建会话。
- 前端有专家管理页（卡片画廊 + 抽屉编辑）。

> 机制：专家与能力的物化、选择语义见 README 契约摘要的 `/experts`、`/sessions` 能力选定段；页面形态见
> [`expert-management.md`](./expert-management.md)。

### 5.1 应用与市场（App & Market）

**应用（App）** 是把一个业务场景打包成一等对象——组合既有 expert / automation / skill / mcp，可选携带
自己的工具域、后端 Slot、页面入口与实体归属，可**整体启停**。应用定义走 `/apps` 六接口（与专家面同构），
管理面另有 6 个 MCP 工具（`app_create` 等，恒注入），因此**通过对话即可创建/编辑应用**。

- **怎么开口（使用说明 v42）**：应用是「组合 + 扩展点」的技术对象，光看它由什么组成，用户不知道该怎么用自然语言驱动它。
  故应用定义多三个字段——`tagline`（一句话「对它说什么」，≤40 字）、`examples`（≤6 条可直接发送的示例话术）、
  `usage_guide`（≤600 字：适用场景 / 需要提供什么 / 产出 / 边界）。卡片只留 `tagline` 概要，示例与用法收进「查看用法」弹层；
  点示例话术即带 `capabilities.apps:[id]` + 这句话开新会话——「看见 → 试一下 → 用起来」。老应用缺这三字段时从
  `description` / 成员派生兜底，不空转。`usage_guide` 是**给人看的用法**，不是模型 system prompt。
- **我的应用页**（`/extensions/my-apps`）：列出**全部** app 定义——包括只通过对话创建、没有独立页面的应用
  （此前这类应用在界面上不可见）。卡片显示生命周期 `state` 徽标（运行中 / 等待中 / 启动失败 / 未启用，失败态带原因）、
  `tagline` 概要、启停开关与「查看用法 →」入口；示例话术 / 用法 / 组成 / 卸载都在弹出的「查看用法」弹层里（与 MCP 详情同源的居中弹窗）。
- **应用市场页**（`/extensions/market`）：浏览可安装的应用卡片（图标 / 名称 / 摘要 / `tagline` / 版本 / 装态）并一键
  安装 / 启用 / 卸载；卡片同样有「查看用法 →」，**装之前**就能预览它能做什么、怎么开口，弹层底栏按装态给「安装 / 启用 / 更新」。
  清单来自内置 `market.json`（`go:embed` 随包分发）或可换源的远端 registry；远端不可达时
  三级兜底（远端 → 磁盘缓存 → 内置），离线可用。安装复用二期 C 的 `apppkg` 校验（清单 / 完整性 sha256 /
  min core version 门槛），装到本地应用目录；`url` 远程分发（需签名链）本期不做，卡片置灰。
- **安全**：`source.dir` 经来源根越界校验（防指向任意本地路径）；安装默认不自动启用；应用页面仍由沙箱 iframe 承载。

> 设计见 [`.dsh/docs/specs/2026-11-10-app-market-design.md`]（本地工作区，未入库）；接口见 README 契约摘要
> `/apps`、`/apps/market` 段。

## 6. 定时任务（Automation）

按计划自动发起会话。

- **计划形态**：`once`（一次性）、`daily`、`weekly`（`0=周日` 的整数集合）、`interval`（≥60 秒）、
  `monthly`（每月某日），显式 IANA 时区；**没有 cron、没有 hourly**。
- **触发投递**：投递回既有会话（默认 `after_run` 不打断）或新开会话；一次触发只有一个事实源（会话状态即运行状态）。
- **认领三态**：`duplicate → overlap → claimed`，同一 occurrence 至多触发一次；`overlap` 跳过但不排队。
- **停机恢复**：启动时收敛，过期的 `once` 不补跑，`daily`/`weekly` 补最近一次。
- **运行史**：含 `skipped` / `overlap` / `duplicate`——没跑成的那些也如实可见；手动触发走同一认领判据但不动游标。

> 机制：载体分叉（sqlite 表 vs 文件）、认领 CAS、投递目标见 [`architecture.md`](./architecture.md) §5，
> 完整语义在 README 契约摘要的 `/automations` 段。

## 7. 工作空间

会话运行在一个工作空间目录里（也是原生权限 `workspace-write` 的边界）。

- **登记表**：用户登记工作空间（`/workspaces`），是选择器与左栏分组的唯一事实源。
- **全系统浏览**：任意已存在目录都能浏览、都能当工作空间；有宿主原生目录选择器（桌面与浏览器入口都能用，
  抬不起来时退化为应用内浏览）。
- **建子目录**：目录浏览面里可「新建文件夹」。
- **默认工作空间**：未指定 cwd 的会话落在默认工作空间；工作空间建成即不可变（改名/删登记不改它）。

> 机制：登记表、目录浏览、`cwd` 校验与符号链接规范化见 README 契约摘要的 `/workspaces*`、`/files` 段。

## 8. 附件、产物、资料库

近期新增的数据面，都遵循「平台做数据管理、执行归底座或本地存储」：

- **附件**：新会话页可上传图片 / 文档；字节走全局唯一收字节端点 `POST /files`（内容寻址去重），业务侧
  只建索引。图片直投为 image 块，文档 / 大图下沉为 handle + 只读目录白名单。
- **产物溯源**：登记「哪会话 / 哪轮 / 哪个工具」产生了哪个产物（file / text / table / link），只建索引不存字节；
  模型经 `present` 显式声明为交付物的文件会**自动抽取并快照**（write/edit 写出的过程文件不算交付物，不登记），产物可回跳来源会话。
- **资料库**：一棵本地可寻址的目录树（folder / doc / table / link / drive / page），「找」只做结构浏览 +
  关键词子串匹配（**不含**语义检索 / RAG）；产物可一键收录进资料库（引用而非复制）。

> 机制：`/files` 收口、附件投影、产物自动抽取、资料库三表与「无语义检索」判据见
> [`architecture.md`](./architecture.md) §7.6。

## 9. 模型与供应商

- **供应商档案**：一个 OpenAI 兼容端点 + 一把密钥；密钥只写不读回（GET 只给 `has_key`）。可连接自检
  （本地段零出网，可选一次上游探测）。
- **应用层模型清单**：用户显式声明可用模型（发给上游的模型名 + 可选容量 + **思考能力声明**——默认
  effort 与可选 reasoningEfforts，落 `models` 三列），是用户面唯一可见的模型来源。
- **运行时目录**：`/models/catalog` 由底座自报的会话配置项（模型为主，其余选项只展示）；平台不内置任何
  模型清单。候选上的 `model_id` 注解指向平台清单行——平台未声明的候选不可选。
- **会话级选模型**：建会话 / `PATCH /sessions/:id` 用平台模型行 id 指定模型；底座拒绝即失败，绝不静默回落默认。

> 机制：provider/model 身份收口、凭据四层回落、目录派生算法见 [`architecture.md`](./architecture.md) §5.4、
> §7 与 [`decisions.md`](./decisions.md) 的 v24–v27。

## 10. 用量统计

`GET /usage/summary` 按日期聚合轮次 / 时长 / 上下文 / 成本，支持近 7/30 天与自定义区间；用量页展示。
需要 sqlite 持久层（memory 模式返回 `40501`）。另有 `llm` 块汇总内部模型调用的 token 明细。

## 11. 实时事件流与数据管理

- **唯一实时出口** `WS /v1/mate/ws/events`：attach/detach/ping、按会话过滤、`since_seq` 游标续传、历史缓冲
  超限快照回退、慢订阅发 `gap` 帧、心跳与断线重连。
- **数据管理是平台职责**：会话 wire transcript（JSONL，重启存活）、SQLite 持久化（events 事实源 + 会话 / 轮次 /
  消息读模型投影）、能力定义与变更审计。读模型一律可重建（`mate doctor --rebuild-read-models`）。

> 机制：事件类型契约（27 类，冻结）、WS 帧格式、transcript 与读模型见 [`architecture.md`](./architecture.md)
> §6.2 与 README 契约摘要的 WS 段。

## 12. 桌面形态与产品身份

- **交付形态**：桌面（macOS / Windows，随包运行时，用户机器不需要 Go / Node / 预装底座）是主线；浏览器入口
  是开发形态；容器 / 自建二进制是维护态。详见 [`positioning.md`](./positioning.md)。
- **产品身份**：界面与日志叫 `ark-mate`，模型自述身份来自底座的系统提示（平台写 overlay patch + 首轮块兜底），
  用户问「你是什么模型/运行时」时模型如实区分产品与执行层。机制见 [`agents/identity.md`](./agents/identity.md)。
