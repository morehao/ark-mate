2026-10-20 层表路径存在性加 1 条 → **172**：`TestLayerTablePathsResolve`（新文件 `layers_paths_test.go`）。**为什么必须有一条守卫**：`v32Layers` 的 key 与 `deny`、以及 `v32AdapterDeny`，都是**精确字符串**；`backend/internal` 做目录搬迁时把 key 改对、把某条 `deny` 漏改，判据不会红——那条原本非法的边会**静默变合法**，而层表自带的兜底（扫到 0 个包、某包映射不到层）照旧全部正常。判据：`v32Layers` 的每个 key、每个 key 的每条 `deny`、`v32AdapterDeny` 的每一项都必须指向 `backendRoot(t)` 下**真实存在的目录**；只查"目录存在"、不查"有 Go 文件"（`internal/infra` 这类带目录本身没有 Go 文件，但合法），`v32Exceptions` 当前为空、暂不纳入。反证（实跑）：`perl -pi -e 's#"internal/model": \{layer: 0#"internal/__missing__": {layer: 0#' internal/archtest/layers_v32_test.go` 后运行 → `层表路径不存在: internal/__missing__（来自 v32Layers key）` 并 FAIL；还原备份后 PASS。同批修了 `Makefile` 的 `-X` 注入路径：`pkg/runtime.BuildRuntime` → `internal/runtime.BuildRuntime`（`backend/pkg/` 早已不存在，`-X` 对不存在的符号是**静默无操作**，桌面/容器包里的 `BuildRuntime` 从来没被注入过）。

2026-10-20 存量定义导入/导出归位加 2 条 → **171**：`TestDefinitionTransferHasOneHome` + `TestPortAdaptersStayAtAssemblyPoint`（新文件 `transfer_ownership_test.go`）。这一批把 `internal/capabilityio` 拆成 `internal/transfer`（三域的 `Import*`/`Export*` + 域无关框架）与 `registry` 的两个窄端口适配体。**为什么必须有一条守卫**：拆之前同一个概念分居两包——capability 的导入留在 `mechanism/definition`，automation/provider 的在 `capabilityio`——改一条纪律（指纹幂等 / 绝不覆盖 / 备份一次 / 不回写）要改两处，而两处都编译得过；包名本身又与 `internal/capability` 只差后缀，看目录的人无法判断该 import 哪个。三种失效各钉一段：① **第二个家**——六个域入口与框架原语必须全在 `internal/transfer`，`mechanism/definition` 与 `domain/**` 零命中（判据 fail-closed：transfer 目录扫不到生产 Go 文件即 Fatal）；② **旧名复活**——`internal/capabilityio` 目录不得存在（`os.Stat` 命中即红）；③ **职责回流**——`automation.DefinitionFiles` / `provider.Secrets` 的编译期断言必须留在 `internal/registry`（装配点；它同时看得见域端口与机制实现，机制层禁止 import 域），`internal/transfer` 不得出现这两个端口名。反证（实跑 5 条，均红）：把 `ExportAutomationDir` 改名 → ①红；在 `mechanism/definition` 加一个 `func ImportProviderFile()` 桩（能编译）→ ①红；`mkdir internal/capabilityio` → ②红；把 registry 的编译期断言改成 `var _ = AutomationDefinitionFiles{}`（能编译）→ ③红；把 `secrets.go` 复制回 `transfer`（能编译）→ ③红。名字的取舍也记在这里：`capabilityio` / `definitionio` 都是「既有包名 + 后缀」，正是上面第 ② 段要挡的那种歧义，所以新包用 `transfer`（动作名，不与任何域共享词根）。
