# 构建与运行

> 从仓库根 `AGENTS.md` 拆出（2026-10-18）——本文件是分册后的唯一事实源；`AGENTS.md` 只保留入口与硬约束。
> 构建形态与运行配置合在一册：两者共同决定「一次构建、同一份产物、同一套配置」。

## 构建形态

- **底座由构建期固定**（2026-10-10 产品约束「用户不能选 runtime」）：`internal/runtime/build.go` 的 `BuildRuntime` 由 `-X` 注入（`RUNTIME=<id>`；Makefile 的 `build/dev/server/core/desktop` 与 Dockerfile 的 `MATE_RUNTIME` 都透传它），**不注入 = `dsh`**。产品装配走 `runtime.ProductRegistry`：只注册选中的那一个（可以是内置 adapter，也可以是 `runtimes.json` 里同 id 的远程端点），未注册即**启动失败**；`AllBuiltinRegistry`/`AllBuiltinSpecs` 只服务测试与诊断（医生与能力矩阵守卫要看**全部**适配面，否则只注册构建期那一个会让别的适配的守卫静默失效）。用户面零入口：`GET /runtimes` 已删；被撤掉的选择键在各写面**显式拒绝**而不是静默丢弃（收下再丢掉会让用户以为"我指定的生效了"）——会话写面那个已下线的 agent 选择键 → `40001 agent_selection_removed`（读面 `GET /usage/summary` 同一条判据），automation 补丁里的 `target.runtime_hint` → `40001 runtime_selection_removed`（存量定义的残留键会被清除并 WARN）。**`runtimes` 本身没被禁**：skill 的投放声明就叫这个名字（v19 之前 agent 定义上那个同名字段才是被撤的那个面）。adapter 层、注册表、远程接入与隔离表三份**原样保留**：内置适配下线不等于把接入机制删掉——上面的"新增一个 = 新目录 + `xxxSpec()` + 端口实现"就是验收口径，内核里**不得**出现任何内置适配 id 的 `case`/`==` 特判（守卫 `TestInternalHasNoRuntimeIDSpecialCase` 钉住，它挡的正是那个活到最后的内核特判：`modelValueFor` 里的 `switch runtimeID`）。
- **核心从不自带前端资产**（2026-10-10：`//go:embed`、`-tags release`、`pkg/web` 与"单二进制"形态整体删除）：资产只有一份 `frontend/apps/web/dist`，由调用方用 `--web-dir` / `MATE_WEB_DIR` 指给核心，**没给就拒绝启动（退出码 3）**，不存在回落来源；`/meta` 的资产面是 `webPath`/`webDigest`/`webBuildId`（`webSource` 字段已删——来源只剩一种，恒量字段不携带信息）。于是全仓只有一个构建配置，桌面核、容器镜像与 `make dev` 跑的是同一份代码路径。**形态优先级（决策 v8③）**：桌面（`make desktop/*`）是主线交付；容器 / 自建二进制 + 外挂 dist / 浏览器入口属服务端与开发形态（维护态）。理由、代价与实测见 `.dsh/docs/notes/2026-10-10-embed-removal-notes.md`。
- `mate` CLI 无默认子命令：`serve / demo / migrate / transcripts prune / config / capability migrate / doctor`（`capability migrate` 把 skill 定义里的旧 `sources[]` 转成 `runtimes[]`，`--dir` / `--dry-run` 可选；`doctor` 是**只读体检**——资产目录与逐文件摘要、随包载荷清单与入口存在性、载荷 `nodeAbi` 与 `release.json` 的一致性、数据目录可写性、端口占用，`--verify-payload` 对载荷树做全量复算，`--json` 供诊断包/CI 消费；"无法校验"记警告、事实与声明不符才退出 1；v18 起还有**不在册底座的存量体检**一段——按「在不在册」判磁盘遗留目录 / 存量会话 / skill 候选 / 投影覆盖，**一律警告不判红**（不做破坏性迁移），见决策 v18⑨，见计划 M4-5；v23 起还有**读模型**一段（`read-models`：孤儿消息 / 空正文行 / 每会话 `ordinal` 与 `events.seq` 的连续性 / `events_json` 来源是否只在白名单内，**任意一条非 0 即 fail**），`--rebuild-read-models` 是这条只读命令**唯一的显式写动作**（体检报漂移后的出路，默认路径一个字节都不写，守卫 G7 钉住），另有 `mate --version [--json]`（核心版本 + API 契约代数；桌面打包期 `release.json` 的 `coreVersion`/`apiContract` **唯一取法**，见计划 M4-1）。`mate demo` 需本机装构建期固定的那个底座（`echo` 演示底座及其 `acp-serve`/`acp-demo` 子命令已于 M0 删除）。

## 运行配置要点

- 默认仅回环 `127.0.0.1:10001`，**不做鉴权**（单用户场景）：REST、`/health` 与事件流都开放，仅受 Host/Origin 矩阵约束；对外暴露请在反向代理层自行加鉴权。桌面壳反代 `/v1/*` 时不注入任何 `Authorization`，`boot()` 只下发 `streamBaseUrl`。部署见 `docs/deployment.md`。
- **回环面的 Host 白名单 + Origin 矩阵（M3-5，设计 §7.2/§9.1）**：只在回环监听时启用（非回环如 `--addr 0.0.0.0` 不启用并打 WARN，理由见设计 §9.4）——`Host` 的主机部分须是 `127.0.0.1`/`[::1]`/`localhost` **且端口 == 实际监听端口**（取自 `Listener.Addr()`，桌面态是内核分配的随机端口；所以装配顺序是"先绑定 → 再构造策略 → 再装路由"，见 `internal/bootstrap/app`）否则 421；`Origin` 只放行无 Origin（壳内反代/curl/导航）、`mate-app://app` 与自身监听端口上的 http 同源，其余（含 `Origin: null`）403。跨源开发/自建反代用 `MATE_ALLOWED_ORIGINS`（纯 origin，**显式登记口不是默认放开**）登记。判定只有一份实现 `middleware.OriginPolicy.Decide`：REST/`health` 走 v1 组中间件，WS 由 `ctrws.Options.OriginCheck` 在 `websocket.Accept` 之前调同一个对象（WS 路由**不挂**该中间件，与"事件流凭据走带内"同一分线；coder/websocket v1.8.15 的 AcceptOptions **没有** CheckOrigin 字段，库自带校验比矩阵更松）。
- 持久层实现：gorm（`internal/infra/dbclient` 装配 + `internal/persistence/model` 实体 + `internal/persistence/dao` 访问）。**SQLite 用 golib 的 `dbgorm/driver/sqlite`**（匿名引入在 `internal/infra/dbclient`，随 driver 一起注册；URL 由 `dbclient.Open` 拼成 `sqlite://`）。
  **不依赖 CGO（2026-10-12 起，golib v1.32.22）**：该 driver 的引擎换成纯 Go 的 `ncruces/go-sqlite3`（SQLite 编成 wasm 再翻译回 Go）——`CGO_ENABLED=0` 可编可跑。**收益按平台说准**（2026-10-12 本机实测）：编译**不需要 C 工具链**（`CC=false` 照样编出完整产物）；`GOOS=linux GOARCH=amd64` 交叉编译**不需要 C 交叉工具链**、`file` 报 `statically linked`（于是 `scratch`/musl 基底重新可用），而同一交叉编译在 `CGO_ENABLED=1` 下**直接编不过**（`runtime/cgo` 要 C 交叉工具链）——本仓"不做交叉编译"那条旧代价随之消失。**但别记成"永远更静态"**：macOS 上 `0` 与 `1` 编出的二进制逐字节同大小、`otool -L` 逐行相同（都只链系统库），差异只在需要动态 libc 的目标上。代价是**体积**：golib 实测最小程序 **+10.99 MiB**（阈值 ≤12 MiB），本仓 darwin/arm64 的 `mate` 为 55,141,554 字节。**历史别记错**：2026-10-10 曾四处写死 0，而那时的 driver 是 CGO 的 mattn/go-sqlite3，0 注册的 stub 让**桌面核的 SQLite 面运行期不可用**（桌面态一启动就撞墙）；2026-10-11 起四处改成 1 并接受动态链接；**2026-10-12 起四处回到 `CGO_ENABLED=0`**（`Makefile` 的 `core/desktop`、`Dockerfile` 的 build 阶段、两份桌面验收脚本的 `rebuildCore`）。
  **这两件事必须成对**：`0` 只在依赖图里没有 CGO 驱动时才对（否则原样回到上面那个"编得出、连库即死"的静默故障），所以 archtest 第 57 条 `TestSqliteDriverStaysPureGo` 同时钉依赖侧（`go.mod` 里不得出现 `mattn/go-sqlite3` / `gorm.io/driver/sqlite`，且纯 Go 那一套真的在）与构建侧（四个面一律 `CGO_ENABLED=0`）。
  **换引擎后的行为变化如实记**（都由 `internal/infra/dbclient/dbclient_test.go` 显式钉住）：① **外键真的生效了**——wasm 构建带 `SQLITE_DEFAULT_FOREIGN_KEYS=1`（SQLite 官方推荐编译项），DDL 里的 REFERENCES 会拦住孤儿行，`TestAppendEventUnknownSession` 因此翻回"应报错"，`migrate.go`/`provider.go` 里"因为不注入 foreign_keys、写了也不生效"的老注释已改正；② 仍不注入 WAL/synchronous（`journal_mode=delete`、`synchronous=FULL`）；③ `busy_timeout=5000` 由 golib 显式注入（排在所有 PRAGMA 之前）；④ **内存库不再进程内共享**——每次 `Open(":memory:")` 分配新库名（`file:/mem_<n>?vfs=memdb`），要共享得写命名内存库 `file:memdb1?mode=memory`（夹具仍用 `t.TempDir()` 下的文件库，但理由换成"生产就是文件库"，见 `internal/testutil.TempDBPath`、`internal/persistence/store` 的 `openTestDB`）；⑤ 时间列：本仓写入一律 RFC3339Nano（serializer 显式格式化，不是驱动默认值），新引擎默认读写即这一形状，因此**不要**注入 `_timefmt`——它会把读也收窄成同一 layout，外部工具写进来的其它形状就 `Scan` 不回来了。
- **落库格式是硬契约**（`internal/persistence/store/format_test.go` 锁定）：时间列一律 TEXT + RFC3339Nano(UTC)，布尔列一律 INTEGER 0/1。两者都由 `internal/persistence/model` 的 serializer 保证——实体照常写 `time.Time`/`bool`，但**裸 SQL 的入参不经过 serializer**，时间要先用 `model.FormatTime` 格式化、布尔要用 `model.FlagValue` 转换。schema 仍由 `internal/persistence/store` 的自管迁移内核创建（不用 gorm AutoMigrate：它表达不了有序版本、版本拒绝启动与导入 staging 回滚）。
- 持久层 `MATE_STORE=sqlite|memory|auto`：make dev/server 默认 sqlite（库 `~/.ark-mate/mate.db`）；sqlite 才有 runs 读模型与 `/usage/summary`（memory → 40501）。memory 模式以 transcript（`~/.ark-mate/transcripts`）为事实源，`mate migrate` 幂等导入 sqlite。
  **默认工作空间在两种模式下都由装配期建立**（2026-10-11 修）：`MATE_WORKSPACE_DIR`（默认 `<home>/workspaces`）下的 `default/`，sqlite 模式落一行登记、memory 模式落一个进程内登记项（每次启动新 id，`writable=false` 只表示**用户登记表**没处存）。memory 模式原先直接跳过这一步，后果是"未指定 cwd 就发一条消息"报 `40001 workspace_required`——最普通的一条路走不通，而用户什么都没做错。**代建显式关闭**（`workspace_dir` 为空/off）时两种模式都不建：那是配置意图。
- 配置优先级：默认值 < `~/.ark-mate/config/config.json` < `~/.ark-mate/config/env` < 进程 `MATE_*` < CLI flag；非法键名与非法取值启动即报错（枚举型键如 `native_permission`/`mcp_auto_probe`/`store` 都按 `Valid*Modes` 校验并报错，提示里列出合法取值）。**没有例外**：`MATE_STORE` 的非法值同样报错，只有**空/未设**才当 auto（无偏好）——`auto` 本身也是合法取值，含义同未设。`mate config --json` 可查最终值与来源。

  这条早先是反的（`MATE_STORE` 非法值静默回落 auto）。改掉的直接理由是**用户无从察觉**：回落后的 `mate config` 输出与合法的 `auto` 逐字相同；而 auto 会按"DB 文件在不在"解析成 sqlite 或 memory，一个错字（`sqlit`）就可能把人悄悄丢进 memory，表现为"数据丢了"。且查历史，`MATE_STORE` 从引入那版起的取值集就是 `sqlite|memory|auto`，**从未有过今天已非法的取值**，严格化不淘汰任何曾经可用的配置。
